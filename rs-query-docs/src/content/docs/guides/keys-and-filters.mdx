Every cache operation in rs-query — invalidation, refetching, cancellation, removal — selects its targets with the same two primitives: hierarchical `QueryKey`s and filter structs. This guide shows how to structure keys so filters do what you mean, and how the filter types compose.

## Design the key hierarchy first

`QueryKey::new` starts a root segment; `.with(label, value)` appends labelled segments; `.segment(name)` appends a plain one. Keys match by prefix, so a root key addresses every query beneath it:

<Code lang="rust" code={`use rs_query::QueryKey;

let users      = QueryKey::new("users");               // matches everything below
let one_user   = users.clone().with("id", 42);          // users/id=42
let friends    = one_user.clone().segment("friends");   // users/id=42/friends`} />

Each key hashes to a stable `cache_key()` string — the identity the cache, the devtools, and the deduplication table all use.

<Aside type="tip">
Put variable data in labels (`with("id", 42)`), not in segment names. Filters match prefixes segment-by-segment, so `users` catches `users/id=42` and `users/id=42/friends` in one operation.
</Aside>

## Match with `QueryFilters`

`QueryFilters` combines six selection dimensions. Start from `all()` or `with_key()`, then narrow:

<Code lang="rust" code={`use rs_query::{FetchStatus, QueryFilters, QueryStatus};

let filters = QueryFilters::with_key(QueryKey::new("users"))
    .active()                                  // only observed queries
    .stale()                                   // and stale ones
    .status(QueryStatus::Success)              // with data
    .fetch_status(FetchStatus::Idle);          // not currently fetching`} />

| Builder          | Selects                                                  |
| ---------------- | -------------------------------------------------------- |
| `all()`          | Every cached query                                       |
| `with_key(k)`    | Queries whose key starts with `k`                        |
| `.exact()`       | Only the exact key, no prefix matching                   |
| `.active()`      | At least one subscribed, enabled observer                |
| `.inactive()`    | No active observers                                      |
| `.stale()`       | Data is stale by flag or by `stale_time`                 |
| `.status(s)`     | Aggregate status equals `s` (`Pending`/`Error`/`Success`) |
| `.fetch_status(f)` | Fetch status equals `f` (`Idle`/`Fetching`/`Paused`)    |
| `.predicate(p)`  | Closure over a `QuerySnapshot` for anything else          |

Predicates receive a `QuerySnapshot` with `key`, `is_active`, `is_stale`, `fetch_status`, `status`, and `has_data`:

<Code lang="rust" code={`use rs_query::QueryFilters;

let big = QueryFilters::all().predicate(Arc::new(|snap| {
    snap.has_data // select only queries that hold data
}));`} />

## Invalidate with a refetch matrix

`invalidate_queries_filtered` pairs a filter with a `RefetchType`, reproducing TanStack's `refetchType` matrix exactly:

<Code lang="rust" code={`use rs_query::{InvalidateQueryFilters, QueryFilters, QueryKey, RefetchType};

// Mark stale only — refetch happens on next mount/focus:
client.invalidate_queries_filtered(
    InvalidateQueryFilters::new()
                    .filters(QueryFilters::with_key(QueryKey::new("users")))
                    .refetch_type(RefetchType::None),
);

// TanStack default: refetch active, mark inactive stale:
client.invalidate_queries_filtered(
    InvalidateQueryFilters::new()
                    .filters(QueryFilters::with_key(QueryKey::new("users")))
                    .refetch_type(RefetchType::Active),
);`} />

| `RefetchType` | Effect                                    |
| ------------- | ----------------------------------------- |
| `All`         | Refetch every matching query              |
| `Active`      | Refetch active; inactive marked stale only |
| `Inactive`    | Refetch inactive; active marked stale only |
| `None`        | Mark stale without refetching             |

## Refetch, cancel, reset, remove

The remaining bulk operations share the same filter input and return the number of affected queries:

<Code lang="rust" code={`use rs_query::{QueryFilters, QueryKey, RefetchQueryFilters};

let users = QueryFilters::with_key(QueryKey::new("users"));

let n = client.refetch_queries(
    users.clone(),
    RefetchQueryFilters::new().cancel_refetch(true), // supersede in-flight fetches
);
let cancelled = client.cancel_queries(&users);
let reset     = client.reset_queries(&users);      // back to Idle, drops data
let removed   = client.remove_queries(&users);     // evict from the cache`} />

`refetch_all_stale()` is the zero-filter shortcut for "refresh everything stale right now".

## Inspect what matched

`query_snapshots(&filters)` returns the matching `QuerySnapshot`s, so you can preview an operation before running it:

<Code lang="rust" code={`for snap in client.query_snapshots(&users) {
    println!("{} {:?} {:?}", snap.key.cache_key(), snap.status, snap.fetch_status);
}`} />

Mutations select with `MutationFilters` the same way — key, exact, status, paused, predicate — over `MutationSnapshot`s. See the [mutation guide](/guides/mutations/) for the patterns.
