**rs-query** is a Rust port of the [TanStack Query](https://tanstack.com/query) stack. You describe *what* data your application needs with a `Query` and a `QueryKey`; the crate handles caching, deduplication, retries, cancellation, invalidation, offline pause/resume, persistence, and hydration. The reactive layer is generic over [quoin](https://github.com/elcoosp/quoin)'s `ReactiveContext`, so the same code runs headless — or inside a quoin application on **gpui, leptos, dioxus, xilem, or floem**.

No runtime is hardcoded: rs-query depends on `quoin-core` only and spawns work on a shared worker pool with portable timers. Version 0.2 targets **TanStack Query v5 parity** — the porting contract is audited upstream semantics, not a loose inspiration.

## What you get

- **A query engine** — `Query<T>` builders with `stale_time`, `gc_time`, `initial_data`, `placeholder_data`, and `select` transformations; stale-while-revalidate caching with structural sharing.
- **TanStack-exact retry math** — `min(1000 · 2ⁿ, 30 s)` backoff, four retry decision modes, `failure_count` and `failure_reason` surfaced on observers.
- **Mutations with lifecycle hooks** — `on_mutate` with rollback closures, scoped serialization, invalidation wiring, and cache-level callbacks.
- **Filters everywhere** — key prefixes, exact matches, active/inactive, stale, status, and predicates drive `invalidate_queries_filtered`, `refetch_queries`, `cancel_queries`, `reset_queries`, and `remove_queries`.
- **Offline first** — `NetworkMode` semantics, an `OnlineManager` with watch-based connectivity, and paused-fetch resume on reconnect.
- **Persistence and hydration** — per-query persisters with `max_age` and `buster`, whole-client save/restore loops, `dehydrate`/`hydrate` with error redaction, and cross-instance broadcast sync.

## The golden path

Every new user completes the same workflow, headless or in a framework app:

1. Hold a `QueryClient` in your application state.
2. Describe a `Query` with a `QueryKey` and an async fetch closure.
3. Run it with `spawn_query` (headless) or observe it with `use_query` (quoin app).
4. Invalidate the key after a mutation; the cache refetches what is active.

Start with the tutorial below — everything else builds on it.
